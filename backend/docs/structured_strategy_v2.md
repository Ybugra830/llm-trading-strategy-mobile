# Structured Strategy Specification v1 and Deterministic Compiler Proposal

Status: design only. This document does not authorize production rollout or
replacement of the current Python-generation pipeline.

## Goal

Replace free-form LLM Python generation with a constrained intermediate form:

```text
natural language -> LLM JSON spec -> schema/semantic validation
-> deterministic compiler -> existing static validation -> Docker -> backtest
```

The public natural-language request can remain unchanged. The LLM supplies no
Python, imports, helper functions, offsets, or order-execution code.

## Top-level schema

```json
{
  "schema_version": 1,
  "name": "SMA 20/50 Long Crossover",
  "position_mode": "long_only",
  "indicators": [
    {
      "id": "fast",
      "type": "sma",
      "inputs": {"close": "close"},
      "parameters": {"window": 20}
    },
    {
      "id": "slow",
      "type": "sma",
      "inputs": {"close": "close"},
      "parameters": {"window": 50}
    }
  ],
  "entry": {
    "kind": "crossover",
    "direction": "above",
    "left": {"kind": "indicator", "indicator_id": "fast", "output": "value"},
    "right": {"kind": "indicator", "indicator_id": "slow", "output": "value"}
  },
  "exit": {
    "kind": "crossover",
    "direction": "below",
    "left": {"kind": "indicator", "indicator_id": "fast", "output": "value"},
    "right": {"kind": "indicator", "indicator_id": "slow", "output": "value"}
  }
}
```

All Pydantic models use `extra="forbid"`. Indicator IDs are unique identifiers,
numbers must be finite, and recursive expressions have explicit depth and term
limits.

## Indicator contract

| Type | Required inputs | Parameters | Outputs |
|---|---|---|---|
| `sma` | `close` | `window` | `value` |
| `ema` | `close` | `window` | `value` |
| `rsi` | `close` | `window` | `value` |
| `macd` | `close` | `window_fast`, `window_slow`, `window_signal` | `line`, `signal`, `histogram` |
| `bollinger` | `close` | `window`, `deviation` | `lower`, `middle`, `upper` |
| `stochastic` | `high`, `low`, `close` | `window`, `smooth_window` | `k`, `d` |
| `atr` | `high`, `low`, `close` | `window` | `value` |

The compiler owns the mapping to exact `ta` APIs. The LLM cannot provide or
override output names or adapter implementations.

## Value expressions

Constants:

```json
{"kind": "constant", "value": 35}
```

Price references:

```json
{"kind": "price", "field": "close"}
```

Indicator references:

```json
{"kind": "indicator", "indicator_id": "rsi14", "output": "value"}
```

Bounded arithmetic:

```json
{
  "kind": "arithmetic",
  "operator": "add",
  "left": {"kind": "indicator", "indicator_id": "sma20", "output": "value"},
  "right": {"kind": "indicator", "indicator_id": "atr14", "output": "value"}
}
```

Supported arithmetic operators are `add`, `subtract`, `multiply`, and `divide`.
Division by a constant zero is rejected statically; runtime denominators receive
a trusted zero guard generated by the compiler.

## Condition grammar

Threshold/comparison:

```json
{
  "kind": "comparison",
  "operator": "lt",
  "left": {"kind": "indicator", "indicator_id": "rsi14", "output": "value"},
  "right": {"kind": "constant", "value": 35}
}
```

Comparison operators are `lt`, `lte`, `gt`, `gte`, and `eq`.

Crossover:

```json
{
  "kind": "crossover",
  "direction": "above",
  "left": {"kind": "indicator", "indicator_id": "fast", "output": "value"},
  "right": {"kind": "indicator", "indicator_id": "slow", "output": "value"}
}
```

The schema exposes no bar offset. The compiler expands crossover deterministically:

```python
cross_up = left[-2] <= right[-2] and left[-1] > right[-1]
cross_down = left[-2] >= right[-2] and left[-1] < right[-1]
```

Boolean AND/OR:

```json
{
  "kind": "boolean",
  "operator": "and",
  "conditions": [
    {"kind": "comparison", "operator": "lt", "left": {}, "right": {}},
    {"kind": "comparison", "operator": "gt", "left": {}, "right": {}}
  ]
}
```

Unary NOT:

```json
{"kind": "not", "condition": {}}
```

V1 does not support arbitrary Python, function calls, imports, loops, custom
indicators, user-selected bar offsets, short positions, or unbounded nesting.

## Compiler architecture

1. Parse JSON into discriminated Pydantic models.
2. Validate indicator IDs, type-specific inputs/parameters, output references,
   expression depth, condition count, and finite constants.
3. Normalize the validated spec into immutable internal IR nodes.
4. Resolve each indicator to a repository-owned adapter template.
5. Generate Python AST/source containing only trusted imports, helpers,
   `GeneratedStrategy.init`, and `GeneratedStrategy.next`.
6. Insert `not self.position` on entry and `self.position` on exit. Generate
   `self.buy()` and `self.position.close()`; no order action comes from JSON.
7. Format deterministically, hash the source, and run the existing static
   validation as defense in depth.
8. Execute unchanged smoke and held-out backtest stages only in Docker.

## Migration

1. Stabilize and measure the current Python-generation path.
2. Implement schema and compiler behind a disabled feature flag.
3. Add golden spec, compiler snapshot, static validation, and Docker smoke tests.
4. Run both pipelines offline on the canonical reliability matrix; never execute
   unvalidated code outside Docker.
5. Keep the public `/api/v1/strategy-lab/run` request unchanged. During migration,
   `generation.code` can continue to expose the deterministic compiled source.
6. Canary only after semantic-equivalence and reliability gates pass.
7. Remove LLM Python repair only after the structured path proves production
   reliability.

## Reliability assessment

Structured JSON plus deterministic compilation should materially reduce syntax,
import, interface, pandas/`ta` adapter, and crossover failures because those
details leave the probabilistic model boundary. It cannot eliminate provider
availability failures or incorrect natural-language interpretation. A future UI
should therefore show the normalized spec for user confirmation before running
high-impact strategies.
